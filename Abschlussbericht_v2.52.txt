2. WICHTIGSTER BEFUND: VIER FORMELN IM AUFTRAGSTEXT SIND FALSCH
---------------------------------------------------------------
Ich habe die Excel-Vorlage ausgepackt und Zelle für Zelle ausgelesen,
statt mich auf die Abschrift im Auftrag zu verlassen. Dabei zeigte
sich, dass der Auftragstext an vier Stellen auf die falsche Zelle
zeigt:

   Wert  Excel-Zelle  Excel rechnet        Auftragstext sagt
   ----  -----------  -------------------  -----------------
   Y     C18          A / cos(b)           A / cos(m)
   AA    C20          A · tan(b)           A · tan(m)
   AC    C22          Q / cos(e)           Q / cos(n/2)
   f     C31          l + 90               o + 90

Der Grund ist immer derselbe: C27 ist b (nicht m), C30 ist e (nicht
n/2), C36 ist l (nicht o).

Das ist nicht Haarspalterei. d hängt über AA und AC an zwei dieser
Formeln:

   mit den Excel-Formeln:      d = 47.46°   <- Ihr Sollwert
   mit dem Auftragstext:       d = 104.68°  <- falsch
   (und f wäre 122.77° statt 147.23°)

Umgesetzt ist die Excel – genau wie Sie es vorgegeben haben ("Die
Excel-Datei ist die fachliche Referenz"). Nur so kommt der von Ihnen
selbst genannte Regressionswert d = 47.46° heraus.

Falls die Excel an einer dieser vier Stellen einen Fehler enthalten
sollte und Ihr Auftragstext das Richtige beschreibt, sagen Sie mir
bitte Bescheid – dann ändere ich es. Nach dem Zahlenbild spricht aber
alles für die Excel.


3. BERECHNUNG – WAS UMGESETZT IST
---------------------------------
Verwendet wird ausschliesslich Spalte C des Blattes "Winkelberechnung
Kehle  Grat" (Kehle). Die Grat-Variante in Spalte D/E ist nicht
umgesetzt.

Eingaben: genau drei, nicht mehr.
   NH  Neigung Hauptdach (°)
   NL  Neigung Lukarne (°)
   GL  Gefällslänge Lukarne (mm)

Reihenfolge der Auswertung (Excel rechnet zellweise, der Code braucht
eine zirkelfreie Kette):

   Q,R,S,T -> tanU,tanV -> U,V -> U+90,V+90 -> W -> A -> e
           -> l,m -> n,o,p -> b,c -> X,Y,Z,AA -> AB -> AC
           -> AD,AE -> h,i,k -> d -> f,g

Jede einzelne Zeile im Code trägt ihre Excel-Zelle als Kommentar, z.B.

   w.Q = Math.sin(r(NL)) * GL;      // C6  = SIN(C4/180*PI())*C5
   w.AC = w.Q / Math.cos(r(w.e));   // C22 = C6/COS(C30/180*PI())  -> C30 = e

Nichts vereinfacht, nichts umgestellt, nichts durch eigene Geometrie
ersetzt.

Intern wird durchgehend mit voller JS-Genauigkeit gerechnet; erst die
Anzeige rundet auf zwei Nachkommastellen und hängt die Einheit an
(Winkel °, Längen mm).

6. FEHLERPRÜFUNG
----------------
Geprüft wird vor jeder Berechnung: NH > 0, NL > 0, GL > 0.

Zusätzlich NH < 90 und NL < 90. Grund: tan(90°) liefert im Rechner
einen sinnlosen Riesenwert, und aus einer 90°-"Dachneigung" entsteht
ohnehin keine Kehle.

Fehlt ein Wert, ist er leer, 0, negativ, Text, NaN oder Infinity, wird
gar nicht erst gerechnet. Stattdessen steht in der Hauptbox "–" und in
Rot, was fehlt – z.B. "Neigung Lukarne (NL) muss grösser als 0° sein."

Zwei zusätzliche Sicherungen gegen NaN/Infinity:
 - die Wurzeln von AD und AE werden vorher auf negative Werte geprüft
   (über 31 684 Kombinationen nachgerechnet: kommt im gültigen Bereich
   nie vor, die Prüfung ist reine Vorsicht)
 - am Schluss wird jeder der 35 Werte auf Endlichkeit geprüft

Es kann also nichts "NaN" oder "Infinity" auf dem Bildschirm landen.
